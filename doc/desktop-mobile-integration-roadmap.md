# RHermes 桌面与移动端整合路线图

## 目标

以当前根目录应用为唯一前端，实现一套代码覆盖：

- Browser：启动时选择 `?surface=desktop` 或 `?surface=mobile`；不按窗口拖拽尺寸切换界面。
- Capacitor：iOS 与 Android 保持移动端交互。
- Tauri：提供桌面端标题栏、侧栏、标签页与工作区布局。

功能目标是以 Desktop `469b7cabf59a03fb2817fce261c25801889a94db` 为参照，迁入对远程 Gateway 有意义的能力，同时保留移动端可用的操作路径。

## 固定边界

1. 本项目只连接远程 Gateway。`localhost` 也按远程 Gateway 处理。
2. 不在客户端启动、托管、修复或更新本地 Gateway。
3. 不迁入 Electron 专属的本机 PTY、本地文件桥、本机 Git/worktree、SSH 启动、本机更新器等能力。
4. 任何文件、终端、Git、工作区操作均通过已连接的 Gateway API/RPC 执行。
5. 桌面增强不能让移动端失去同一项核心能力；移动端采用 Sheet/Drawer，桌面采用侧栏/面板/快捷键。

## 已完成基础

- 启动期固定 Desktop/Mobile surface，Browser、Capacitor、Tauri 使用同一业务层。
- 远程 Gateway 登录、OAuth 回调、WebSocket 连接、Profile 与连接切换。
- 会话创建、恢复、历史分页、审批/澄清/密钥/Sudo/MCP 设置请求。
- 会话队列、引导当前任务、重试、编辑重发、分支、归档、导出、未读和跨 Profile 会话操作。
- 桌面标题栏、左右侧栏显隐、标签页、命令面板、会话搜索器。
- 远程文件树、文件读写、Git 状态/差异/暂存/提交/推送。
- Skills、MCP、Toolsets、Profile、Webhooks、Cron、消息平台、记忆、学习图谱、日志、Computer Use、模型与 Provider 设置。
- Composer 的附件、文件拖放、Slash 补全、远程 `@` 文件/目录补全、语音转写与 TTS。

“已完成”表示已有代码入口；仍需在真实远程 Gateway 上按阶段验收。

## 迭代路线

### Phase 1：右侧预览工作台（P0）

目的：让桌面端从“文件树 + 文本编辑器”升级为可持续工作的远程工作区。

交付项：

- 文件预览 Tab：文本、图片、PDF/二进制下载提示、Markdown 渲染。
- 远程 URL/HTML 预览：通过受控内嵌 WebView 或外部打开策略展示 Gateway 产出的预览链接。
- 产物页与右侧预览联动；从对话中的文件/链接可直接打开预览。
- 远程终端输出与工作区的单一预览入口；不增加本机终端。
- 可关闭、可切换、可恢复的预览 Tab 状态。

验收：桌面端能从文件树、产物与对话消息打开同一份远程资源；移动端能从 Sheet 打开对应预览或安全外部链接。

### Phase 2：Composer 富交互（P0）

目的：补足 Desktop 输入效率，同时让触屏交互保持简洁。

交付项：

- `@file`、`@folder`、`@url`、`@image`、`@tool`、`@git` 的结构化引用选择和展示。
- 图片粘贴、缩略图、附件失败重试、附件移除与大小/类型提示。
- 引用 Chip 与编辑时的退格导航，避免将远程路径误当成本机路径。
- 桌面键盘导航、快捷键、输入撤销；移动端采用底部选择器与触摸操作。
- 完整的连续语音模式：录音活动检测、转写、打断、自动续录；保留现有单次转写作为降级路径。

验收：任一引用或附件均通过 Gateway 可识别的请求格式发送；在 Browser、移动端和桌面端的行为一致，不访问客户端本地文件路径。

### Phase 3：会话运行状态与任务面板（P0）

目的：让用户在长任务中清楚看到 Hermes 正在做什么，并能安全地干预。

交付项：

- 统一状态栈：目标、思考、工具执行、后台任务、模型等待、压缩、预览链接、子代理进度。
- 可折叠的实时进度与已完成摘要；保留完整对话记录。
- 任务中断、引导、排队、澄清和审批状态的一致排序与去重。
- 会话切换/恢复后重建未完成任务状态，避免旧会话事件串入新会话。

验收：网关发送的运行事件能在当前会话稳定呈现；切换 Profile、切换会话和网络重连后不会误显示其他会话的状态。

### Phase 4：项目与远程 Git 工作流（P1）

目的：补齐桌面端的项目组织能力，但所有操作仍在 Gateway 主机上完成。

交付项：

- 项目元数据：项目名称、工作目录、会话归属、最近活动和基础排序。
- 远程分支选择、工作目录切换，以及由 Gateway 支持时的远程 worktree 创建/切换。
- Git Review 面板：文件状态、差异、暂存、提交、推送、PR 链接回溯。
- 会话与项目之间的移动/筛选；移动端提供等价的 Sheet 流程。

验收：每个 Git 操作明确显示目标 Gateway 工作目录；不调用本机 Git、不创建客户端本地 worktree。

### Phase 5：侧边栏信息架构（P1）

目的：把对话、Cron 和消息平台会话变成可管理的工作队列。

交付项：

- Cron 任务侧栏摘要：下次执行、最近结果、快速暂停/恢复/触发。
- 消息平台会话：平台图标、未读聚合、平台级分页、跳转到平台设置。
- 会话颜色/标签、项目归属调整、会话排序与筛选。
- 桌面 Tab 批量关闭、恢复上次标签布局；移动端保持单会话导航语义。

验收：Cron、消息平台和普通会话互不挤占；全部 Profile 视图中的操作始终作用于行所属的 Profile。

### Phase 6：扩展与个性化（P2）

目的：迁入非核心但有价值的 Desktop 扩展能力。

交付项：

- Gateway 插件页面与贡献点入口；Kanban 等插件采用远程 API。
- 主题市场与外观预设。
- 宠物、HUD、快速入口等桌面增强，作为可选功能并确保可关闭。
- 多窗口/分屏会话：优先实现 Tauri 支持，Browser 退化为 Tab/Panel。

验收：任一扩展在不可用的平台有明确降级，不阻塞核心会话、Gateway 连接或移动端启动。

## 平台差异规则

| 能力 | Desktop surface | Mobile surface |
|---|---|---|
| 导航 | 常驻侧边栏、Tab、命令面板、快捷键 | Drawer、Sheet、单会话返回路径 |
| 工作区 | 右侧文件/预览面板 | Workspace Sheet |
| Composer | 键盘导航、拖放附件、紧凑控制条 | 触摸优先、底部弹层、文件选择器 |
| 会话并行 | 标签页与后续分屏 | 单会话聚焦，后台队列保留 |
| 文件与 Git | 远程面板与 Review | 远程 Sheet，保留核心查看/编辑/提交能力 |

## 非目标

以下能力不纳入本路线图，除非后续明确改变“远程 Gateway-only”边界：

- 本地 Gateway 安装、启动、关闭、升级和诊断修复。
- Electron 主进程特权能力、本机 PTY、本机终端、SSH bootstrap。
- 客户端本机文件系统读写、Git/worktree 管理、本地媒体协议。
- 桌面安装包更新器、签名、发布和系统级窗口覆盖层。

## 每阶段完成标准

每个阶段完成前应满足：

1. 功能通过 Gateway API/RPC 实现，且目标 Profile/连接明确。
2. Desktop 与 Mobile 各有可达入口或明确、合理的降级路径。
3. 不引入本地 Gateway、PTY 或客户端本机文件系统依赖。
4. 至少完成 TypeScript 检查与 diff 检查；涉及 Gateway 契约时补充相应的模拟/契约测试。
5. 原生容器启动、打包与发布验证单独安排，不作为功能开发阶段的默认阻塞项。
